## Summary

This RFC lists every item `design/07` names for v0.1 "The Garage", plus the `[v0.1]` items in
`design/13`, and records the following for each one:

- its current backend, player-surface and content state, with evidence;
- the RFC that owns it;
- what is missing;
- the other items it depends on.

It then orders the owning RFCs into a dependency DAG with tiers that can run in parallel,
proposes the batches Marco should accept together, and defines the v0.1 exit criteria.

This RFC authorizes no mechanic and no release. It is the "release RFC" input that
`phase0-manifest-proposal.md` §"Decisions and proof still required" item 3 asks for, applied to
the milestone *after* the preview.

## Motivation and authority boundary

1. **The preview comes first.** Owner rulings D-001 and D-007 (2026-08-21,
   `planning/platform-alignment/owner-ruling-packet.md`) made the Phase-0 Playable Preview the
   next target: T0–T1 only, "explicitly not roadmap v0.1". This manifest does not widen the
   preview. It plans the next milestone, and it inherits the preview's release floor F01–F05
   unchanged: the ruling packet says a release label cannot waive those obligations.
2. **Why it is needed now.** `planning/roadmap-1.0.md` records v0.1 as "Not yet scoped in accepted
   release RFC". Six new content and surface drafts are being written in parallel. Without one
   manifest they would re-derive their dependency edges independently and could leave items with
   no owner. §1 found five such items: Clout mint and PR Interns, cosmetic ownership, pet adoption,
   the ticker content slice, and headcount allocation if it is not specified inside
   `tier2-content`.
3. **Out of scope.** This RFC does not specify mechanics, balance numbers, copy text or schemas.
   It does not edit `design/07`. Reconciling `design/07` with the preview ruling is the owner's
   task (see OQ-1). It does not authorize any v0.2+ item: factions as a play surface, community
   milestones, Events Layer 2, or the board-game suite.

**Draft-set caveat.** At the evidence coordinate, the six new drafts (`rfc/tier2-content.md`,
`rfc/reputation-tree-v1.md`, `rfc/minigame-terminal-typer.md`, `rfc/minigame-server-garden.md`,
`rfc/minigame-demo-disc-arcade.md`, `rfc/garage-player-surfaces.md`) do not yet exist in the tree.
Their assumed scope in this RFC comes from their assigned titles. **Acceptance criterion MC-2
requires this manifest to be re-reconciled against their actual bodies before acceptance.** In
particular, an item marked *UNOWNED* here may turn out to be claimed by one of them.

## Specification

### Legend

- **Backend:** `Live` means code, a canonical doc and an artifact pinned in the current epoch.
  `Impl-inactive` means code exists but no content is pinned or activated. `Fixture` means the
  code is tested but the content lives only in test data. `Partial` means some but not all of
  the needed code exists. `Absent` means no code.
- **Surface:** `Mounted` means reachable in `client/src/game-ui/surfaces.json`. `Stub` means
  rendered but not stateful. `None` means not rendered.
- **Content:** `Pinned` means in epoch 8. `Design-only` means the content exists only in
  `design/` or `design/research/`.
- **Owner states:** `archived` (implemented), `implementing`, `accepted`, `draft`, `new-draft`
  (being written now), and `UNOWNED`. An `UNOWNED` item has no draft; this RFC proposes a name
  for one, and the proposal is not authority.

### §4 — Exit criteria for v0.1

v0.1 is complete only when **every** criterion below holds at one release artifact. Each one uses
the eight dimensions of `planning/roadmap-1.0.md` §What counts as done. An archived foundation or
a green unit suite never satisfies a row on its own.

- **EC-1 Preview floor.** P01–P07 and F01–F05 are proven on the v0.1 bundle, not inherited from a
  preview run.
- **EC-2 Manifest completeness.** Every in-scope G and X row has four things. (1) An implemented,
  archived owning RFC with canonical `docs/`. (2) A real producer → generated-client API →
  mounted surface → pinned content path. (3) A composed browser workflow witness that fails when
  its producer is severed (evidence discipline 1). (4) A recorded cross-party designated verdict
  whose ranges union to the full span. Out-of-scope rows appear in the owner-ruled exclusion
  list, and none is silently dropped.
- **EC-3 Pacing.** The harness passes the adopted T0–T2 targets as acceptance gates (`design/07`
  principle 1). Those targets are: first generator < 60 s; T1 about 15 min; first elective Exit
  45–90 min for Chaos p50 and Casual p95; run-2 Garage strictly faster; the OQ-8
  first-minigame target; the tier2-content T2 target; Earnings Call day-2. Measurement is
  fail-loud, with no guard-terminated runs (evidence discipline 3).
- **EC-4 Laws.** The following are each proven by a negative test. There is no real-money path
  anywhere; the `$0.00` shop and Horse Armor carry their curtain-pull disclosure. Every cap is a
  visible hardcap. Offline progress applies at the default 90%/24 h. The feed and counters work
  with zero players online through the NPC fallback, and bots and NPCs pass the same
  validation. The Clout mint matches the OQ-5 ruling, and a seeded second faucet is rejected. The
  pet layer is reviewed as sincere.
- **EC-5 Rights and data.** Every new v0.1 data class (cosmetic ownership, pet records, Garden
  collections, minigame sessions, any ghost data if OQ-2 admits it) appears in the D-008 export
  schema, the D-009 deletion disclosure and the D-015 retention policy, with a joined deletion
  witness.
- **EC-6 Accessibility.** R-005 passes for every v0.1 task under the D-018 matrix. That includes
  minigame play, the tier-up ceremony (with reduced motion), and ticker announcements, which must
  not flood AT live regions.
- **EC-7 Satire and content.** The "small business opens its doors" beat is present across T0–T2,
  the shop and the ticker. Every real-world statistic traces to a `design/research/` citation.
  Nothing on a research file's verify-before-shipping list ships as fact. The Arcade uses
  mechanics only, with no trade dress or names. All player copy is owner-adopted.
- **EC-8 Comprehension.** R-008 is re-run on the v0.1 first session, including the T2 allocation
  decision and at least one minigame. It meets the R-008 thresholds.
- **EC-9 Operations.** R-006 and R-007 pass on the exact v0.1 candidate and previous bundles. That
  includes a save migration across the v0.1 epoch.
- **EC-10 Canon.** The RFC index, `docs/`, the roadmap board and the execution queue agree with
  HEAD. Marco makes an explicit release call.
