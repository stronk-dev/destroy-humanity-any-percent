# Combat Shared Data & Arithmetic lifecycle audit

Coordinate: product tree `190a4fa`; audit checkpoint after `628db4e`; 2026-08-20.

This pass re-derived the active Combat parent from its full RFC, plan/log, Go and TypeScript
arithmetic/RNG authorities, shared vector corpus, AST boundary gate, canonical doc, child status,
implementation history, and review records. Temporary discrimination mutations were restored. No

## Bottom line

The implemented kernel is real and discriminating in both runtimes:

- staged exact damage rejects omission of non-identity ATK scaling independently in Go and TS;
- labeled SplitMix64 substreams reject a label-insensitive implementation independently in both;
- the six-cycle chart rejects loss of a winning edge independently in both; and
- the client boundary rejects a real nested `.mts` file containing native division by exact path.

AC2, AC3, and AC4 are therefore promoted. The broader parent remains blocked because its two
missing halves are specification gaps, not implementation laziness:

- C2 promises a closed move-effect union and spell/lane schemas but never enumerates their members
  or exact fields, so AC1's strict loader and complete Phase-0 fixture cannot be authored; and
- C5 supplies neither literal Trust→Obedience nor Soul table points, domains, interpolation/clamp,
  or composition order, so AC5 cannot have honest cross-runtime golden vectors.

AC6 is not promoted as written. Its client half is excellent, but C3 says no native `/` anywhere in
combat paths and AC6 says the `/` lint fails a seeded violation in `combat/`. The gate scans only
`client/src/combat`; `server/combat/arithmetic.go` contains the active native integer division and
is not examined. The arithmetic is correct, but the literal all-path law and its acceptance claim
are contradicted until the ruling author narrows them to TypeScript or supplies a Go boundary.

## Producer-to-consumer trace

1. `server/determinism` owns Go SplitMix64/rejection sampling; the balance harness aliases it.
2. `client/src/combat/rng.ts` owns the TypeScript equivalent but is consumed by Active Play,
   Fiscal, Pitch, replay, and Combat. The resource is shared even though the path is combat-named.
3. Go and TypeScript Combat arithmetic consume the shared JSON vectors and expose no battle state.
4. No strict catalog or Phase-0 combat content exists. Search finds no `balance/combat` family.
5. No duel/lane engine or bot/integration child is accepted for implementation; no player surface
   exists. The current capability is a shared math/determinism primitive, not combat gameplay.
