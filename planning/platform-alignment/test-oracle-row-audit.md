The absence of an integrated row does not erase useful integration evidence. Fifty-one functions
exercise real Postgres when the declared Compose/hosted lane runs cold, and the external composed
browser script proves bootstrap through presence. The row audit refuses to combine those separate
or conditional witnesses into an unconditional end-to-end gameplay result. The composed browser
script is also outside the frozen `it`/`test` declaration population and stops before gameplay.

## Mandatory fired controls

- The Game UI C11 axe declaration is `non_discriminating`: removing cap explanation, drain notice,
  and resync story output together left the complete browser population green. Axe remains useful
  for mechanical accessibility findings, not those semantic outcomes (RP-026).
- API generation is only `bounded_discriminating` for registered operations. A registered
  optional-field mutation failed `api-check`, while a mutation to an unregistered hand-mounted
  live route stayed green. It cannot prove full v1 coverage or a generated client (RP-060–RP-063).
- The production client-boundary linter and hosted harness/cache failures are command-level oracles,
  not row declarations. No row in this population repairs their fired failures (RP-056–RP-059,
  RP-064–RP-065).
- The desired lifecycle-focus and 320 px probes failed in all three browser engines. They are
  intentionally absent from the current declared population, so the green browser rows remain
  fixture-only and cannot claim those workflows (RP-082–RP-084).
- All 51 real-Postgres rows retain `dependency_conditional`. The separate cold Compose executions
  recorded in `test-evidence-audit.md` are valid bounded evidence; ordinary `make test-go` green is
  not (RP-101).
- The architecture-gated Commons overflow test is `invalid_or_guarded` on a host where it skips;
  its package green cannot be universalized.

## Promotion and denominator controls

Every bounded promotion was reviewed against its exact declaration/body identity and structural
assertion signals. Blanket promotion by package was rejected: Decimal and Combat rows without an
explicit rejection or a previously fired exact-runtime mutation remain `positive_only`. The eight
arithmetic/vector declarations tied to restored mutations receive bounded credit only, as does the
registered API generator row.

The validator reproduces all 802 identities and body hashes from the structural ledger, enforces
the exact verdict distribution, and rejects seeded dropped/duplicate/body-drift,
conditional-as-integrated, helper-as-positive, blind-oracle-promotion, and missing-route cases. It
also pins the fired Game UI and API boundary controls.

This is an evidence classification, not a test rewrite or an acceptance completion. Product tests,
fixtures, bounds, design/RFC bodies, canonical product docs, and implementation-plan checkboxes are
unchanged. Rows routed to an accepted RFC still require exact range-union review and the designated
cross-party pass before archival.
