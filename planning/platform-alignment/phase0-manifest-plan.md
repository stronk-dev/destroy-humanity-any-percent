# Phase-0 release-manifest evidence plan

Status: research only; no release-scope adoption or implementation authority.
Coordinate: current product source `7e8aa70`, current planning HEAD at execution.
Owner: D-007 exact release manifest; downstream D-018 accessibility tasks and R-006 release proof.

## Question and population

Which exact T0–T1 player tasks, content rows and supporting service obligations can the
Phase-0 Playable Preview honestly promise? Enumerate the current epoch-8 artifact composition,
mounted Game UI surfaces, production API consumers, and the default composed browser journey.
Include the adopted D-001/D-007 boundary and public-release floor. Exclude T2+ and deferred
Advisor Mode, asynchronous minigames, gameplay telemetry and public UGC from the candidate.

## Method and controls

1. Read the canonical roadmap, T0–T1 content document, active RFC register, adopted owner
   rulings and current capability audit. Treat their dates and claims as leads, not runtime proof.
2. Trace each candidate task through server producer, API/transport, mounted client control,
   epoch-8 content and an executable witness. Record missing links explicitly. The seven
   governed first-hour milestones are the progression population, not automatic proof of UI.
3. Check a negative control: at least one epoch-8 artifact with no mounted player task must
   remain outside the preview promise. Check a positive control: Gate/Exit/next-run must map
   to the designated-approved composed Game UI witness and real content.
4. Keep required public-hosting obligations (rights, accessibility, recovery, operations) on
   the release floor even if they lack a player surface today. Distinguish mandatory floor from
   already-proven scope and owner-selectable inclusion.

## Exit and limitations

Produce a dated evidence matrix and a proposed exact manifest with task IDs, content boundary,
included/deferred/unresolved status, proof and blockers. The proposal must name the D-007 choices
for Marco and the D-018 task dependency without silently accepting either. A static source trace
cannot prove usability, full pacing, clean-host behavior or legal sufficiency; only the designated
integration/rehearsal studies may do so. No product or authored content changes in this wave.
